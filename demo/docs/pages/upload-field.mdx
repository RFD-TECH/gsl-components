# UploadField

File upload with a dashed-border dropzone, cloud upload icon, support text derived from `accept` (or written yourself via `subtitle`), file cards with type icons and size, and a primary action button. Supports single and multiple files, accept filters, max size validation, controlled/uncontrolled value, and `react-hook-form` integration.

## Usage with react-hook-form

`UploadField` integrates with react-hook-form through `FormField`. Pass `field.value` and `field.onChange` directly:

### Native validation

```tsx
import { useForm } from "react-hook-form";
import { Form, FormField, Field, FieldControl, FieldLabel, FieldError, UploadField } from "@rfdtech/components";

function UploadForm() {
  const form = useForm<{ file: File | null }>({
    defaultValues: { file: null },
  });

  return (
    <Form {...form}>
      <form onSubmit={form.handleSubmit((data) => console.log(data.file))}>
        <FormField
          control={form.control}
          name="file"
          rules={{ required: "Please select a file" }}
          render={({ field, fieldState }) => (
            <Field invalid={!!fieldState.error}>
              <FieldLabel>Document</FieldLabel>
              <FieldControl>
                <UploadField
                  value={field.value}
                  onChange={field.onChange}
                />
              </FieldControl>
              <FieldError>{fieldState.error?.message}</FieldError>
            </Field>
          )}
        />
      </form>
    </Form>
  );
}
```

### Zod validation

Install the optional peer dependencies:

```bash
npm install react-hook-form zod @hookform/resolvers
```

Define a Zod schema with `z.instanceof(File)` and refine for file type and size:

```tsx
import { zodResolver } from "@hookform/resolvers/zod";
import { useForm } from "react-hook-form";
import { z } from "zod";
import {
  Button,
  Field,
  FieldControl,
  FieldError,
  FieldLabel,
  Form,
  FormField,
  UploadField,
} from "@rfdtech/components";

const ACCEPTED_TYPES = ["image/png", "image/jpeg", "application/pdf"];
const MAX_SIZE = 5 * 1024 * 1024; // 5 MB

const uploadSchema = z.object({
  file: z
    .instanceof(File, { message: "Please select a file" })
    .refine((f) => ACCEPTED_TYPES.includes(f.type), {
      message: "Only PNG, JPEG, and PDF files are accepted",
    })
    .refine((f) => f.size <= MAX_SIZE, {
      message: "File size must be 5 MB or less",
    }),
});

type UploadFormValues = z.infer<typeof uploadSchema>;

function UploadForm() {
  const form = useForm<UploadFormValues>({
    resolver: zodResolver(uploadSchema),
    defaultValues: { file: null },
  });

  const onSubmit = (data: UploadFormValues) => console.log(data.file?.name);

  return (
    <Form {...form}>
      <form onSubmit={form.handleSubmit(onSubmit)}>
        <FormField
          control={form.control}
          name="file"
          render={({ field, fieldState }) => (
            <Field invalid={!!fieldState.error}>
              <FieldLabel>Upload file</FieldLabel>
              <FieldControl>
                <UploadField
                  accept=".png,.jpg,.jpeg,.pdf"
                  maxSize={MAX_SIZE}
                  value={field.value}
                  onChange={field.onChange}
                />
              </FieldControl>
              <FieldError>{fieldState.error?.message}</FieldError>
            </Field>
          )}
        />
        <Button type="submit" variant="primary">
          Submit
        </Button>
      </form>
    </Form>
  );
}
```

Omit per-field `rules` when using a Zod schema resolver — Zod handles all validation.

For multiple files use `z.array(z.instanceof(File))`:

```tsx
const uploadSchema = z.object({
  files: z
    .array(z.instanceof(File))
    .min(1, "Select at least one file")
    .refine((files) => files.every((f) => f.size <= MAX_SIZE), {
      message: "Each file must be 5 MB or less",
    }),
});
```

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `accept` | `string` | — | Accepted MIME types (also drives the subtitle text) |
| `multiple` | `boolean` | `false` | Allow multiple file selection |
| `maxSize` | `number` | — | Maximum file size in bytes (drives the subtitle text; files exceeding this are silently filtered) |
| `subtitle` | `ReactNode` | derived | Overrides the hint under the title. Pass `""` to drop the line entirely |
| `value` | `File \| File[] \| null` | — | Controlled value |
| `onChange` | `(file: File \| File[] \| null) => void` | — | Change handler |
| `invalid` | `boolean` | `false` | Show error border styling |
| `disabled` | `boolean` | `false` | Disable interaction and dim appearance |
| `name` | `string` | — | Form field name (for react-hook-form) |
| `fileStatuses` | `UploadFieldFileStatus[]` | — | Optional per-file status overlay (`uploading`/`completed`/`failed`), index-aligned with `value` |
| `onCancel` | `(file: File, index: number) => void` | — | Called from the cancel (×) control on an `"uploading"` file |
| `onRetry` | `(file: File, index: number) => void` | — | Called from "Try Again" on a `"failed"` file |
| `classNames` | `UploadFieldClassNames` | — | Part-level class overrides |
| `className` | `string` | — | Merged onto the root element |

Also accepts remaining `HTMLAttributes<HTMLDivElement>`, excluding `onChange`, `value`, and `defaultValue`.

## File type detection

When files are added, the component detects the file type and shows a matching icon:

| Type | Detection | Icon |
|------|-----------|------|
| Image | `type.startsWith("image/")` or extension `.png`, `.jpg`, `.webp`, etc. | `FileImage` |
| Video | `type.startsWith("video/")` or extension `.mp4`, `.webm`, etc. | `FilePlay` |
| PDF | `.pdf` extension | Custom PDF icon |
| Other | Everything else | `FileText` |

File size is formatted automatically: `B`, `KB`, or `MB`. The same detection logic is available standalone via the exported `FileFormatIcon` component (`<FileFormatIcon file={file} size={20} />`) — useful for rendering a matching icon outside of `UploadField`, e.g. in a custom file list.

## Notes

- The subtitle is derived from `accept` and `maxSize` (e.g. "Only CSV files are supported. Maximum filesize 10MB."). Every entry in `accept` is named, so `accept=".pdf,.jpg,.jpeg"` reads "Only PDF and JPG files are supported.", and `accept="image/*,.pdf"` reads "Only image and PDF files are supported.". Pass `subtitle` to write the line yourself, or `subtitle=""` to remove it. With no `accept` and no `maxSize` there is nothing to say, so no subtitle is rendered.
- `accept` is passed to the native input, which filters the OS file picker only. It is **not** enforced on drag-and-drop: a dropped file of the wrong type is still accepted. Validate type yourself in `onChange` if that matters.
- File names are checked before a file is accepted, and a selection containing an unsafe name is rejected whole. The rejected name is shown with the offending characters replaced by `U+FFFD`, so a name cannot disguise itself inside the error dialog either. Four cases are refused:

| Reason | Example | Why |
|--------|---------|-----|
| `control-character` | `shell.php\0.jpg` | A NUL truncates the name in a C string API, so the extension a server validates and the file it writes can differ |
| `path-separator` | `../../etc/passwd` | The name can escape its directory once joined to a path |
| `bidi-override` | a name containing `U+202E` | Reorders the rendered text so the real extension reads as something harmless |
| `empty` | `""` | Nothing to store or display |

  The same rule is exported as `findUnsafeFileNameReason(name)` and `isSafeFileName(name)`, so an app can run it before sending anything to its API.

  > This is defence in depth and a usability affordance, **not** a security boundary. Anything in the browser is bypassed by posting to the API directly, so the server has to run the same check on the name it receives. Note also that a browser will rarely hand you a name containing a NUL, because filesystems reject it; the value here is in the drag-and-drop and programmatic paths, and in telling a real user plainly why their file was refused.
- The action button changes text: "Upload file" when empty, "Replace file" when a file is selected. Only shown in single-file mode (`multiple={false}`).
- Drop zone turns `--clet-primary-light` background when files are selected or during drag-over.
- When `multiple` is true, selecting or dropping new files **replaces** the current set (no append) — this applies to picking new files via the input/drop zone, not to `fileStatuses`, which stays index-aligned with whatever `value` currently holds.
- Controlled mode: pass `value` and `onChange`. Uncontrolled mode: let the component manage its own state.
- If **every** newly selected file exceeds `maxSize`, an "Upload failed" dialog appears with a "Try again" action. If only **some** files in a multi-file selection exceed it, those are silently filtered from the accepted set — handle finer-grained per-file validation externally via `fileStatuses`/`onChange` instead.
- Removing a file via the trash icon removes only that file from the array in multi-file mode — it does not clear the whole selection.
- The failed-state card gets a `--clet-error` border and tinted background; no new colors were introduced for any status — uploading uses `ProgressBar`'s default (`--clet-primary`) variant, completed uses `--clet-success`, failed uses `--clet-error`.
