# AppLayout

Application layout container that auto-positions `AppHeader`, `AppSidebar`, and `AppBody` by component type. Wraps `SidebarProvider` and `BreadcrumbProvider` internally. Breadcrumbs render from `useBreadcrumbs()` context, no `AppBreadcrumb` slot needed.

## Variants

`AppLayout` accepts a `variant` prop that controls how the header, sidebar, and body are arranged.

- **`"default"`** (default): the sidebar runs the full height against the viewport edge, and the header sits flush across the top of the content column only. Nothing is inset and nothing is rounded.
- **`"panel"`**: the same column order, but the sidebar, header and content float as inset rounded panels over the page background. This was the `"default"` arrangement before 2.3.
- **`"stacked"`**: the header spans the full width on top, with the sidebar and content side by side below it.

The default is one third of the layout shell, and the three parts are designed to be adopted together: `AppLayout` (no variant) with [`Sidebar variant="primary"`](/docs/sidebar#variants) for the brand rail and [`AppHeader variant="plain"`](/docs/app-header#variants) for the top bar. Branding lives at the top of the rail, not in the header.

## Hiding the chrome

`hideHeader` and `hideSidebar` drop those regions whatever children were passed. Nothing renders in
their place: the wrapper element is not emitted, no column or row is reserved, and the content
takes the space. Neither flag changes the children, so the same tree renders whole when they are
off.

This is for an app that runs both standalone and as a remote in a federated shell. The host draws
the chrome once, and each remote renders the same layout with the flags on so it does not draw a
second header or a second rail inside the host's:

```tsx
<AppLayout hideHeader={isRemote} hideSidebar={isRemote}>
  <AppHeader>…</AppHeader>
  <AppSidebar>
    <Sidebar variant="primary">…</Sidebar>
  </AppSidebar>
  <AppBody>
    <Outlet />
  </AppBody>
</AppLayout>
```

`SidebarProvider` and `BreadcrumbProvider` are still mounted while a region is hidden, so
`useSidebar()` and `useBreadcrumbs()` keep working in a remote whose sidebar the host owns.

## Components

### `AppLayout`

Root layout container. Scans direct children for `componentId` matching `"AppHeader"`, `"AppSidebar"`, or `"AppBody"` and positions them automatically. Breadcrumbs are rendered between the header and body when `useBreadcrumbs()` is called from any child. `SidebarProvider` and `BreadcrumbProvider` are wrapped internally, no need to add them manually.

| Prop | Type | Description |
|------|------|-------------|
| `children` | `ReactNode` | Direct children — `<AppHeader>`, `<AppSidebar>`, `<AppBody>` |
| `className` | `string` | Merged onto the root element |
| `variant` | `"default" \| "panel" \| "stacked"` | Layout arrangement. `"default"`: flush full-height sidebar, header across the content column. `"panel"`: the same columns as inset rounded panels. `"stacked"`: full-width header on top, sidebar + content side by side below. Defaults to `"default"`. |
| `hideHeader` | `boolean` | Drops the header even when an `<AppHeader>` child is passed. Nothing renders in its place and no space is held. |
| `hideSidebar` | `boolean` | Drops the sidebar even when an `<AppSidebar>` child is passed. The content takes the full width. |

### `AppSidebar`

Wrapper for sidebar content. Must be a direct child of `AppLayout`. Renders inside a flex column with `max-content` width. Typically contains `<Sidebar>`.

| Prop | Type | Description |
|------|------|-------------|
| `children` | `ReactNode` | Sidebar content — typically `<Sidebar>` |
| `className` | `string` | Merged onto the sidebar wrapper |

`AppSidebar` renders no extra DOM element — it passes children through. The sidebar wrapper div is created by `AppLayout`.

### `AppBody`

Wrapper for main page content. Must be a direct child of `AppLayout`. Renders as `<main>` inside the content area.

| Prop | Type | Description |
|------|------|-------------|
| `children` | `ReactNode` | Page content — includes `<AppHeader>` if desired, plus body content |
| `className` | `string` | Merged onto the `<main>` element |

> Note: `AppHeader` renders above `AppBody` when both are direct children of `AppLayout`. If `AppHeader` is placed inside `AppBody`, it renders inline within the content area without the sticky header wrapper.

## Breadcrumbs

Breadcrumbs are rendered automatically by `AppLayout` when items are set via `useBreadcrumbs()`. No `<AppBreadcrumb>` wrapper or `<BreadcrumbProvider>` needed.

```tsx
import { useBreadcrumbs } from "@rfdtech/components";

function Page() {
  useBreadcrumbs([
    { label: "Users", href: "/users" },
    { label: "Current User" },
  ]);
  return <div>Page content</div>;
}
```

When `items` is empty, the breadcrumb section is hidden entirely.

## Types

### `AppLayoutProps`

| Key | Type | Description |
|-----|------|-------------|
| `children` | `ReactNode` | Direct children for auto-positioning |
| `className` | `string` | Root CSS class |
| `variant` | `"default" \| "panel" \| "stacked"` | Layout arrangement: `"default"` (flush shell), `"panel"` (inset rounded panels) or `"stacked"` (full-width header on top). Defaults to `"default"`. |

| Key | Type | Description |
|-----|------|-------------|

## Design tokens

| Token | Fallback | Used for |
|-------|----------|----------|
| `--clet-app-layout-body-gap` | `1rem` | Gap between layout sections in `"panel"` and `"stacked"` |
| `--clet-app-layout-gap` | `1rem` | Outer padding and flex gap in `"panel"` and `"stacked"` |
| `--clet-app-layout-padding` | `2rem` (`1rem` at 768px and below) | Content and header inset in the default arrangement: the line the page title and the header search both start on |
| `--clet-panel-bg` | `--clet-surface-subtle` | Content area background in `"panel"` |
| `--clet-panel-radius` | `--clet-radius-2xl` | Content area and body border radius in `"panel"` |
| `--clet-app-layout-font` | `--clet-font-body` | Font family for the root layout element |
| `--clet-scroll-fade` | `1` | Opacity multiplier for the top/bottom scroll fade overlays on the `"panel"` body |
| `--clet-scroll-fade-height` | `calc(var(--clet-app-layout-body-gap) * 3)` | Height of the bottom (and, unless overridden, top) scroll fade overlay |
| `--clet-scroll-fade-width` | `100%` | Width of the top/bottom scroll fade overlays |

## Notes

- The header is sticky (`position: sticky; top: 0`), so it stays visible when the body scrolls.
- `AppLayout` sets `height: 100vh; overflow: hidden` on itself and `overflow-y: auto` on the body area — the page scrolls within the body while the sidebar stays fixed.
- The sidebar has `flex-shrink: 0` with `width: max-content`, so it sizes to its content and won't shrink.
- All three components are optional — you can use only `AppBody` for a simple content shell, or `AppSidebar` + `AppBody` for a sidebar layout without a header.
- Auto-positioning works by reading `componentId` from the child element's render function — only direct children are scanned.
- Do NOT wrap children in Fragments, conditionals, or unknown elements — `AppLayout` only auto-positions components with `componentId` matching `"AppHeader"`, `"AppSidebar"`, or `"AppBody"`. Anything else is silently ignored and won't render.
- Breadcrumbs are rendered from context. Call `useBreadcrumbs()` from any child, AppLayout handles the rest. When items is empty, breadcrumbs are hidden.
- Content area background differs by variant: `"panel"` fills the content area with `--clet-panel-bg` (a distinct panel card); `"default"` and `"stacked"` let `--clet-main-bg` show through, so the content reads flush with the page rather than as a separate panel.
- The sidebar column sits one level above the header in the stacking order, so the mobile drawer and its backdrop cover the header when open rather than sliding out beneath it.
- Upgrading from 2.2 or earlier: `variant="default"` used to mean the inset panel arrangement, which is now `variant="panel"`. `rfdui migrate --preserve` pins every existing `AppLayout` to `"panel"`; `rfdui migrate` leaves them on the new default. See the [migration guide](/docs/migration-v2).
