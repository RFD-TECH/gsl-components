# Table

Compound table component with built-in URL-driven search, pagination, filters, column sorting, selection, bulk actions, and loading skeletons. All state lives in the URL — components read and write search params internally. Pass `paramPrefix` to `<Table>` to namespace state for multiple tables on one page.

## Soft variant

`Table variant="soft"` is the current preferred table. It restyles the controls the table already
composes rather than introducing new ones:

- The header puts **filters on the left and inputs on the right**, and rounds the filter trigger,
  the search field and any `Dropdown` into pills on a faint shadow.
- **Pagination** draws the current page as a filled `--clet-info` disc, collapses Previous/Next to
  their chevrons, and keeps "Showing X-Y of Z" with the page-size pill together on the left.
- Pair it with `TableContent variant="soft"` for the tinted header band and hairline row rules.

```tsx
<Table paramPrefix="submissions" variant="soft">
  <TableHeader>
    <TableSearch placeholder="Search submission" />
    <TableFilter variant="spread">
      <Dropdown options={statuses} placeholder="All Statuses" aria-label="Filter by status" />
    </TableFilter>
  </TableHeader>
  <TableContent variant="soft" columns={columns} data={rows} />
  <TableFooter noBorder>
    <TablePagination totalPages={totalPages} totalItems={total} />
  </TableFooter>
</Table>
```

Every one of those controls is the ordinary component with its ordinary API: the variant reaches
them by drilling down from the root `.clet-table--soft` class. So keep composing `Dropdown`,
`TableSearch` and `TablePagination` as normal: there is no separate soft filter or pagination
component, and hand-rolling one loses their URL-state and keyboard handling. `TableHeader` children
stay in their usual order too; the left/right swap is the variant's own.

| Token | Fallback | Used for |
|-------|----------|----------|
| `--clet-table-control-radius` | `999px` | Pill radius on the filter, search and dropdowns |
| `--clet-table-control-shadow` | `--clet-shadow-soft` | Lift under those pills: the same shadow the soft `MetricCard` uses |
| `--clet-table-page-size` | `32px` | Diameter of the pagination discs |
| `--clet-info` | `#098be6` | Fill of the current-page disc and the prev/next chevrons |

## Spread filter variant

Pass `variant="spread"` to `<TableFilter>` to drop the popover entirely — the
fields render inline as a flex row (with a consistent gap) directly in the
toolbar, with just a "clear" action — no Apply button. Fields auto-apply as
soon as their value changes (no popover to dismiss, so there's nothing an
explicit Apply click would gate). Same `onApply`/`onReset` and URL behavior
as the default popover variant otherwise, just no trigger button or panel.

## Filter fields: two rules

`<TableFilter>` collects its values from the form it wraps, so a field joins the
table's state only when it renders a named form control. Both variants enforce
this in development and report a violation to the console.

1. **Every field carries a `name`.** The name is the filter key: `name="status"`
   writes `?<prefix>.f_status=`. A field without one keeps its value to itself,
   filters nothing, and is left behind by "clear": it looks wired up while
   doing nothing. `Dropdown` and `Combobox` both take `name`.
2. **Every field is seeded from the URL.** Read the initial value from
   `useTableState({ paramPrefix }).filters` so a reload, a shared link or a
   back-navigation restores the selection the URL describes. A field that
   renders a different value than its param is reported the same way.

```tsx
const { filters } = useTableState({ paramPrefix: "members" });
const [status, setStatus] = useState(filters.status ?? "");

<TableFilter variant="spread">
  <Combobox
    name="status"
    value={status || null}
    onValueChange={(v) => setStatus(v ?? "")}
    options={statusOptions}
    placeholder="All statuses"
  />
</TableFilter>;
```

"clear" empties every named field, including controlled ones a native form
reset cannot reach, and removes only the filter params the form owns. A param
belonging to something else on the page is left alone.

## Architecture

Every child component reads and writes its own URL keys through `useSearchParams`. The root `<Table paramPrefix>` provides a shared namespace via React Context. No prop drilling — pass `totalPages` and `totalItems` to `<TablePagination>`; everything else is fully automatic.

```
<Table paramPrefix="members">
  <TableSearch />              → writes ?members.search=term
  <TableFilter>                → writes ?members.f_role=admin
    <Dropdown name="role" value={roleValue} onValueChange={setRoleValue} ... />
  </TableFilter>
  <TableContent />             → renders data + sort headers
  <TableBulkActions />         → shows selection bar with inline actions
  <TablePagination />          → reads/writes ?members.page=1&members.pageSize=10
</Table>
```

Filter fields must be *named* form-associated elements for `FormData` to capture them — never a raw `<select>`/native `<button>`/native `<input>` as the visible control. `Dropdown` participates in native form submission on its own via its `name` prop (backed by Radix's hidden bubble `<select>`) — no separate hidden input needed. Other custom inputs without built-in form participation still need a hand-paired `<input type="hidden" name="...">`.

Multiple tables on one page share the same URL without collision by using different prefixes:

```tsx
<Table paramPrefix="members">{/* ... */}</Table>
<Table paramPrefix="invoices">{/* ... */}</Table>
// URL: ?members.page=1&invoices.page=2&invoices.search=paid
```

## `<TableFilter>`

Popover with filter fields and Apply / Reset buttons. Wraps children in a `<form>` element. On Apply, reads `FormData` from named fields and writes `f_{name}={value}` to the URL. On Reset, clears all `f_*` params.

Filter fields must be *named* form-associated elements for `FormData` to read them — never a raw `<select>`/native `<button>`/native `<input>` as the visible control. Pass `name="status"` straight to `Dropdown` and it participates in native form submission on its own (backed by Radix's hidden bubble `<select>`) — the `name` becomes the URL key. Other custom inputs without built-in form participation still need a hand-paired `<input type="hidden" name="...">` driving the same value.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `children` | `ReactNode` | — | Filter form content (inputs with `name` attributes) |
| `onApply` | `() => void` | — | Optional callback when Apply is clicked (URL write happens first) |
| `onReset` | `() => void` | — | Optional callback when Reset is clicked (URL clear happens first) |
| `applyLabel` | `string` | `"Apply Filter"` | Apply button text |
| `resetLabel` | `string` | `"Reset"` | Reset button aria-label |
| `variant` | `"popover" \| "spread"` | `"popover"` | `"spread"` removes the popover and lays fields out inline as a flex row — see [Spread filter variant](#spread-filter-variant) |
| `classNames` | `TableFilterClassNames` | — | Part-level class overrides |
| `className` | `string` | — | Merged onto the root div |

## `<TableContent>`

Renders a `<table>` with columns, data, optional sort, row selection, and loading skeletons.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `variant` | `"default" \| "panel" \| "soft"` | `"default"` | `"panel"` renders a faint recessed surface with subtle row dividers and a border all around; `"soft"` drops the outer border for a tinted header band and hairline row dividers (both CSS-only overrides) |
| `columns` | `TableColumn<T>[]` | — | Column definitions |
| `data` | `T[]` | — | Row data |
| `rowKey` | `(row: T) => string \| number` | — | Unique key extractor for each row |
| `loading` | `boolean` | `false` | Show skeleton rows instead of data |
| `loadingRows` | `number` | `5` | Number of skeleton rows to display |
| `selectable` | `boolean` | `false` | Show a checkbox selection column with select-all in the header |
| `selectedIds` | `Set<string \| number>` | `new Set()` | Controlled set of selected row keys. Pass with `onSelectionChange`. Required for `TableBulkActions` sync. |
| `onSelectionChange` | `(selectedIds: Set<string \| number>) => void` | — | Called with a new `Set` on any selection toggle |
| `rowActions` | `TableRowAction<T>[]` | — | Row-level actions rendered as a kebab dropdown at the end of each row. Opens from the kebab button on click, or at the cursor position on right-click anywhere in the row — see [Row actions](#row-actions) below. |
| `bulkActions` | `TableBulkAction[]` | — | Surfaces bulk actions inside the row-actions menu (kebab click or right-click) as a "Bulk actions" section — always includes a Select all/Deselect all toggle, with the rest of the list appearing once one or more rows are selected. Requires `selectable`. See [Row actions](#row-actions) below. |
| `bulkActionsFooter` | `boolean` | `false` | Also render the `TableBulkActions` bar at the bottom of the table automatically, wired to the same `bulkActions`/`selectedIds` — skip placing `<TableBulkActions>` yourself as a sibling. When `false`, `bulkActions` only surface inside the row-actions menu. |
| `onRowClick` | `(row: T, event: MouseEvent<HTMLTableRowElement>) => void` | — | Called when a row is clicked. Fires in addition to selection toggling when `selectable` is set — use it to e.g. open a detail view on row click. |
| `className` | `string` | — | Merged onto the wrapper div |
| `virtualRowHeight` | `number` | — | Row height in px. Set this to enable virtual scrolling. The parent `<Table>` must have a `height` set. |
| `emptyIcon` | `ReactNode` | Inbox icon | JSX/ReactNode icon shown above the empty text when `data` is empty. Defaults to an Inbox icon from `lucide-react`. |
| `emptyText` | `string` | `"No results"` | Message shown when `data` is empty |
| `classNames` | `TableContentClassNames` | — | Part-level class overrides |

When `selectable` is true, a checkbox column is always present, collapsed to 0 width when no rows are selected. The header checkbox selects or deselects all visible rows.

Rows show hover state and cursor pointer when `selectable` or `onRowClick` is set.

### Row actions

`rowActions` is the **preferred** way to add a per-row action menu — prefer it over hand-rolling a `Popover` per row (see the CRUD example below, kept only for cases needing fully custom menu content). It renders a single kebab-triggered dropdown that opens two ways:

- **Kebab click** — opens anchored to the kebab button, right-aligned underneath it, same as any dropdown trigger.
- **Right-click anywhere in the row** — opens at the exact cursor position (`clientX`/`clientY`), not snapped to the kebab column. This lets users right-click near the data they care about instead of hunting for the actions column. Right-clicking the same row again while its menu is already open closes it, instead of re-opening at the new cursor position.

Both open the same menu and share the same `TableRowAction<T>[]` items — no extra wiring needed.

```tsx
<TableContent
  columns={columns}
  data={rows}
  rowKey={(row) => row.id}
  rowActions={[
    { id: "view", label: "View", icon: <Eye size={14} />, onClick: (row) => openView(row) },
    { id: "edit", label: "Edit", icon: <Edit size={14} />, onClick: (row) => openEdit(row) },
    {
      id: "delete",
      label: "Delete",
      icon: <Trash2 size={14} />,
      variant: "destructive",
      onClick: (row) => deleteRow(row.id),
    },
  ]}
/>
```

**Bulk actions in the row-actions menu.** Pass `bulkActions` (requires `selectable`) to surface bulk actions inside that same kebab/right-click menu, under a "Bulk actions" section label. A Select all/Deselect all toggle always shows there; the rest of `bulkActions` only appears once one or more rows are selected. Add `bulkActionsFooter` to also render the `TableBulkActions` bar at the bottom automatically — otherwise `bulkActions` only ever surface inside the menu, and you place `<TableBulkActions>` yourself if you want the bottom bar:

```tsx
<TableContent
  columns={columns}
  data={rows}
  rowKey={(row) => row.id}
  selectable
  selectedIds={selected}
  onSelectionChange={setSelected}
  rowActions={rowActions}
  bulkActions={[
    { id: "export", label: "Export", icon: <Download size={14} />, onClick: (ids) => exportRows(ids) },
    { id: "delete", label: "Delete", icon: <Trash2 size={14} />, destructive: true, onClick: (ids) => deleteRows(ids) },
  ]}
  bulkActionsFooter
/>
```

Need a plain row click instead (e.g. navigating to a detail page)? Use `onRowClick` — it fires independently of `rowActions` and of selection toggling:

```tsx
<TableContent
  columns={columns}
  data={rows}
  rowKey={(row) => row.id}
  onRowClick={(row) => navigate(`/members/${row.id}`)}
/>
```

## `<TableBulkActions>`

A bar that appears when rows are selected, showing "Selected N" on the left and action buttons on the right. Place it as a child of `<Table>`, between `<TableContent>` and `<TableFooter>`. Auto-hides when no rows are selected (`selectedIds.size === 0`).

Action handlers receive `selectedIds` automatically — consumers never reference the selection state directly in their handlers.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `selectedIds` | `Set<string \| number>` | — | **Required.** Currently selected row keys. Auto-hides when empty. |
| `selectedCount` | `number` | `selectedIds.size` | Override displayed count |
| `onClear` | `() => void` | — | Called when the X clear button is clicked |
| `actions` | `TableBulkAction[]` | — | Predefined actions rendered as inline buttons |
| `renderActions` | `({ selectedIds }) => ReactNode` | — | Render prop for custom action content. Replaces the default buttons. |
| `classNames` | `TableBulkActionsClassNames` | — | Part-level class overrides |
| `className` | `string` | — | Merged onto the root bar |

### Basic usage

```tsx
const [selected, setSelected] = useState<Set<string | number>>(new Set());

<Table paramPrefix="users">
  <TableContent
    selectable
    selectedIds={selected}
    onSelectionChange={setSelected}
    columns={columns}
    data={users}
    rowKey={(u) => u.id}
  />
  <TableBulkActions
    selectedIds={selected}
    actions={[
      {
        id: "delete",
        label: "Delete",
        icon: <Trash2 size={14} />,
        onClick: (ids) => deleteUsers(ids),
        destructive: true,
      },
    ]}
  />
</Table>
```

`selectedIds` is controlled — pass it alongside `onSelectionChange` so both `TableContent` and `TableBulkActions` read from the same source. `onClear` on `TableBulkActions` resets the shared state. Add `rowActions` to render a per-row kebab dropdown.

### Custom render

Use `renderActions` to replace the button group with your own content:

```tsx
<TableBulkActions
  selectedIds={selected}
  renderActions={({ selectedIds }) => (
    <>
      <Button size="sm" variant="outline" onClick={() => handleCustom(selectedIds)}>
        Custom
      </Button>
    </>
  )}
/>
```

## `useTableState`

**Recommended** — the single hook for all table state. Reads page, pageSize, search, filters, and sort from URL params. Use it to derive filtered/paged data from your raw dataset. Prefer this over `useTableFilter` and `useTablePagination` individually.

```tsx
const { page, pageSize, search, filters, pageSizeOptions } = useTableState({
  defaultPageSize: 10,
  paramPrefix: "members",
});
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `defaultPage` | `number` | `1` | Initial page when URL has no value |
| `defaultPageSize` | `number` | `10` | Initial page size |
| `pageSizeOptions` | `number[]` | `[10,20,50,100]` | Options passed to pagination dropdown |
| `defaultSearch` | `string` | `""` | Initial search term |
| `defaultFilters` | `Partial<TFilters>` | — | Initial filter defaults |
| `defaultSort` | `{ column, direction } \| null` | `null` | Initial sort state |
| `paramPrefix` | `string` | — | Must match `<Table paramPrefix>` |

**Returns:** `{ page, pageSize, pageSizeOptions, setPage, setPageSize, search, setSearch, filters, setFilters, setFilter, sort, setSort, resetAll }`

Filters are stored as `Record<string, string>`. Values from URL are always strings — coerce in your filtering logic as needed. Use `filters.status ?? ""` to provide a default.

## `useTableFilter`

Standalone hook for URL-driven filter state without search, pagination, or sort.

```tsx
import { useTableFilter } from "@rfdtech/components";

const { filters, setFilter, setFilters, resetFilters } = useTableFilter({
  defaults: { role: "admin" },
  paramPrefix: "members",

```

| Option | Type | Default |
|--------|------|---------|
| `defaults` | `Record<string, string>` | — | Default filter values |
| `paramPrefix` | `string` | — | URL key namespace |

**Returns:** `{ filters, setFilter, setFilters, resetFilters }`

## Notes

- All URL writes are `replace: true` except page changes which use `pushState` for back-button support.
- Changing search, filters, or page size automatically resets to page 1.
- Sort is client-side only (`localeCompare`). No server integration.
- Loading skeletons use a pulse animation; reduced-motion users get a static version.
- Without a `paramPrefix`, keys are plain (`page`, `search`, `f_status`). With one, they are namespaced (`members.page`, `members.search`, `members.f_status`).
- `paramPrefix` is required on `<Table>` — every table must have a unique namespace to avoid URL collisions.
- The filter form captures all elements with a `name` attribute via `FormData`. For custom inputs (date pickers, multi-selects), ensure they set a `name` and participate in `FormData`.
- Selection is page-local: "select all" only selects rows on the current page. Selection is fully controlled via `selectedIds` / `onSelectionChange` — pass the same `selectedIds` to `TableBulkActions` for sync.
- At `768px` and below (matching the breakpoint `Sidebar` uses for its mobile drawer), `TableHeader`'s children stack full-width instead of squeezing into one row, both `TableFilter` variants stack their fields, `TablePagination` wraps and centers its two rows (results/page-size, then prev/pages/next), and the bulk-actions bar wraps instead of clipping.

## Do

- Use the `TableActions` slot inside `TableHeader` for toolbar-level filters or actions (e.g. a `Dropdown` filter) that are distinct from per-row `TableRowAction`s and bulk `TableBulkActions`.
- Prefer `rowActions` over a hand-rolled per-row `Popover` for kebab menus — it gets cursor-anchored right-click for free, alongside the standard kebab-click trigger.
- Prefer `bulkActions` + `bulkActionsFooter` on `TableContent` over manually pairing it with a standalone `<TableBulkActions>` sibling — one prop pair keeps the row-actions menu's "Bulk actions" section and the bottom bar in sync automatically. Reach for a standalone `<TableBulkActions>` only if you need it placed somewhere `TableContent` can't reach (e.g. outside `<Table>` context) or without the in-menu section.

## Don't

- Don't pull `TableSearch`, `TableFilter`, `TableActions`, or a view-mode toggle out of `<Table>` context into a plain `<div>` — these children require the ancestor `<Table paramPrefix>` to function.
- When a page has a list/tile view toggle, don't rebuild `TableHeader` per mode — keep it (search, filters, toggle) identical for both, and only swap `TableContent` (list) for a grid (tiles) inside `<Table>`.
- Don't hand-roll `onContextMenu` + a controlled `Popover` to get a cursor-anchored right-click menu — `rowActions` already does this.
